# Skin 功能指南

本文說明 IINA-ANI 目前 Skin 的使用方式、作者配置能力與限制。適用於現行 Skin schema／組件契約 v1；精確檔案格式及組件識別表見 [Skin 作者格式與範例](../Examples/Skins/README.md)。

## 1. Skin 與 Layout 的分工

| 項目 | 負責內容 | 不會改變的內容 |
| --- | --- | --- |
| Skin 外觀 | 色彩、字型、字級、間距、圓角、邊框、密度、圖片素材、狀態樣式與預設頁面動效 | 作品、收藏、帳號、下載與播放能力 |
| Layout 佈局 | 頁面、組件位置、尺寸、分欄、分頁、寬度斷點及頁面自訂動效 | 業務資料與來源權限 |
| 個人覆寫 | 對目前第三方 Skin 調整字級與密度 | 作者原包與其他 Skin 的個人設定 |

Skin 可以附帶作者 Layout，但**預設只套用外觀**。必須明確選擇作者佈局並確認，才會取代目前排列。已套用的作者 Layout 之後獨立存在，切換或移除 Skin 不會自動還原原先佈局。

Skin 不是播放器主題或網站 CSS，不能修改 IINA／mpv 的整套介面，也不能替換原生控制項程式、增加來源能力或跳過安全確認。

## 2. 功能入口

可在「設定 → 外觀與佈局」搜尋 `Skin`、`主題` 或相關設定名稱；固定「外觀」選單也提供操作，不依賴作者 Layout 是否保留設定頁。

| 操作 | 用途 |
| --- | --- |
| Skin 管理與預覽／Skin 管理… | 查看已安裝包、選擇外觀、匯入、移除及匯出 |
| 匯入 .iinaskin | 開啟主題包，驗證後進入預覽 |
| 明暗模式 | 選擇跟隨系統、淺色或深色 |
| 個人字級與密度／此 Skin 的文字與密度… | 修改目前第三方 Skin 的個人外觀 |
| 選取作者目錄並預覽 | 直接讀取本機作者目錄，不必先壓縮 |
| 重載作者目錄並預覽 | 重新驗證已選作者目錄的修改 |
| 匯出作者原包 | 分享作者內容，不加入個人覆寫 |
| 匯出個人外觀與選定佈局 | 建立具有新 ID 的衍生包 |
| 預覽並套用作者佈局 | 將目前 Skin 附帶的 Layout 套用至工作區 |
| 移除目前 Skin | 移除安裝包；若為目前外觀，恢復內建外觀 |
| 恢復內建外觀 | 切回內建樣式，保留已安裝包及現有 Layout |

管理窗口顯示名稱、版本、作者與授權。作者及授權均是包內宣告，**不是經驗證的作者身份或權利證明**。選取「內建外觀」時，移除與匯出按鈕停用，因為它不是第三方安裝包。

## 3. 匯入、預覽與切換

### 匯入新主題

1. 選擇「匯入 .iinaskin…」，或將單一 `.iinaskin` 拖入 Skin 管理窗口；由 App 開啟包檔也走相同驗證流程。
2. App 驗證檔案、資源、版本與格式。失敗時先修正錯誤，不會將不完整包當成可用外觀。
3. 若與已安裝包具有相同 ID 但內容不同，先檢視版本與檔案差異，再決定是否替換。相同 ID、相同內容不重複安裝；版本號不代表自動更新授權。
4. 在原生預覽窗口查看效果。頂部保留名稱、版本、作者、授權及套用選項。
5. 只換皮時保持作者 Layout 選項不勾選，按「套用此外觀」；確定需要改排列時，勾選後按「套用外觀與作者佈局」。

預覽使用隔離狀態，不執行播放、下載等業務命令。取消不保存安裝、外觀或佈局變更；預覽不是正式內容播放驗收。若預覽期間已安裝內容、個人覆寫或目前工作區改變，App 會拒絕過期提交，應重新預覽。

### 切換已安裝主題

在管理窗口選中包，按「預覽並套用…」。切換仍需預覽確認，不因選中列表就立即套用。沒有附帶作者 Layout 的包，對應選項不可用。

## 4. 明暗模式與個人覆寫

### 明暗模式

「明暗模式」提供跟隨系統、淺色、深色。選擇後先預覽，確認才保存。

- 作者以 `supportedVariants` 宣告支援 `light`、`dark`，不能以 `system` 宣告第三種變體。
- `theme.json` 的 `system` 是明暗兩種外觀共用的樣式，不等同於使用者的「跟隨系統」選項。
- 選到作者未提供的變體會拒絕切換，不會自動反色或從其他 Skin 拼接樣式。

### 個人字級與密度

需先套用第三方 Skin，再開啟「個人字級與密度」：

- 字級輸入範圍為 **10–32 pt**。
- 密度可選緊湊、標準、寬鬆，對應 `compact`、`regular`、`comfortable`。
- 先預覽再套用；取消不保存。
- 設定按 **Skin ID** 分開保存，切回同一 ID 時可沿用，不直接修改作者檔案。

目前此介面只提供字級與密度，不是任意色彩、素材、槽或狀態的視覺化編輯器。其他作者樣式需編輯包內 JSON／素材，再重新載入預覽。

## 5. 色彩、文字與幾何樣式

作者在 `theme.json` 設定共用／明暗樣式，必要時再以 `components.json` 細分。未指定的屬性沿用內建值，不必完整重寫整套外觀。

| 屬性 | 功能 | 格式／範圍 |
| --- | --- | --- |
| `foreground` | 文字或前景色 | 6／8 位十六進位色碼，可帶 `#` |
| `background` | 背景色 | 同上 |
| `borderColor` | 邊框色 | 同上 |
| `fontFamily` | 字型名稱 | 非空字串；未指定採系統字型，無法取得指定字型時回退系統字型 |
| `fontSize` | 字級 | 有限數值，0–2048 |
| `spacing` | 間距 | 有限數值，0–2048 |
| `radius` | 圓角 | 有限數值，0–2048 |
| `borderWidth` | 邊框寬度 | 有限數值，0–2048 |
| `opacity` | 不透明度 | 0–1 |
| `density` | 內容密度 | `compact`／`regular`／`comfortable` |
| `backgroundAsset` | 背景圖片 | `manifest.assets` 中的素材 ID |
| `iconAsset` | 圖示 | 同上 |
| `placeholderAsset` | 缺圖／等待等佔位素材 | 同上 |
| `decorationAsset` | 裝飾素材 | 同上 |

數值上限是格式安全邊界，不是建議設計值；作者格式的字級範圍也不等於個人覆寫介面的 10–32 pt。各屬性只作用於實際使用它的呈現位置，不保證每個原生控制項都使用全部屬性。

可直接修改 [minimal/theme.json](../Examples/Skins/minimal/theme.json) 作為起點。它包含 `system`、`light`、`dark` 三個物件；只想更換色彩時，保留共用設定並調整明暗色碼即可。

## 6. 公開槽、組件覆寫與互動狀態

### 公開槽

槽是穩定的呈現位置名稱，不是 Swift 類名、CSS selector 或任意介面路徑。

| 槽 | 用途 |
| --- | --- |
| `workCard` | 作品卡片 |
| `list` | 清單 |
| `search` | 搜尋介面 |
| `navigation` | 導覽 |
| `primaryAction` | 主要操作 |
| `tabs` | 分頁 |
| `progress` | 進度 |
| `background` | 背景 |
| `icon` | 圖示 |
| `placeholder` | 佔位呈現 |
| `decoration` | 裝飾 |

組件另外公開 `panel`、`header`、`row`、`emptyState` 等槽，具體名稱依組件登記。完整 component ID 與可用槽見[作者格式](../Examples/Skins/README.md)的「theme、components 與 cascade」組件表；不可把某組件的槽名任意用到另一組件。

### 配置方式

`components.json` 有兩個頂層物件：

- `slots`：共用槽樣式。
- `overrides`：以穩定 component ID 為索引，為指定組件覆寫槽樣式，例如只修改搜尋面板的標題，而不改其他面板。

每個槽樣式使用 `values` 與 `states`；`values` 是基本屬性，`states` 依目前互動狀態補充或覆蓋。可參考 [full/components.json](../Examples/Skins/full/components.json)，不要使用 Swift 類名當識別。

| 狀態 | 意義 |
| --- | --- |
| `normal` | 一般狀態 |
| `hover` | 指標停留 |
| `pressed` | 按下 |
| `selected` | 選中 |
| `focus` | 焦點 |
| `disabled` | 停用 |
| `loading` | 載入中 |
| `error` | 錯誤 |

只有控制項實際具有的狀態才會顯示。缺少自訂狀態時保留基本樣式與原生焦點／停用呈現；Skin 不能使不可操作的按鈕變成可操作，也不能隱去業務錯誤的語義。

### 優先順序

先以內建值作缺省值；作者的 `system` 與目前明暗變體合併，再使用共用槽和組件槽覆寫。槽內依序套用 `values`、`normal`、目前狀態，最後套用此 Skin 的個人覆寫。

因此，如果修改全域色彩卻看不到某區變色，先檢查該區是否有槽、組件或狀態覆寫；字級與密度則另檢查個人覆寫。

## 7. 圖片與字型素材

- 圖片支援可實際解碼的 **PNG／JPEG**，用於背景、圖示、佔位與裝飾。
- 字型支援可經 CoreText 解碼的 **TTF／OTF**；以 `font` 開頭的素材 ID 必須附 `assetAttributions` 授權歸屬。
- 在 `manifest.assets` 宣告素材 ID 與包內相對路徑，樣式引用 ID，不直接引用檔案路徑或遠端網址。
- 狀態圖片需要基本回退：若在非 `normal` 狀態設定某種素材角色，須在該樣式的 `values` 或 `normal` 中提供同角色素材。
- 包內可包含 `preview.png` 展示圖，但展示圖不能代替 App 的真實原生預覽。

圖片以目標顯示大小產生縮圖並使用有容量限制的快取。沒有遠端圖片下載槽，也不支援 SVG、HTML、影片背景、音效或 shader。素材授權由作者負責；作業系統字型可用名稱引用，不表示可以把其字型檔再散布。

## 8. 頁面動效

Skin 可提供預設進場動效，在 manifest 的 `entryPaths` 明列 `pageMotion` 路徑，例如 `motions/page.xml`。未明列便不會自動尋找或載入 XML。

```xml
<pageMotion version="1" duration="0.25" opacity="0"
            offsetX="0" offsetY="16" scale="1" curve="easeOut"/>
```

| 欄位 | 功能與限制 |
| --- | --- |
| `version` | 固定為 `1` |
| `duration` | 秒數，0–5；0 停用 |
| `opacity` | 起始不透明度，0–1 |
| `offsetX`／`offsetY` | 起始水平／垂直偏移，各為 −2048 至 2048 pt |
| `scale` | 起始縮放，0.1–4 |
| `curve` | `linear`、`easeIn`、`easeOut`、`easeInOut` |

全部屬性必填，動效完成後恢復正常位置、大小及不透明度。XML 僅允許指定格式，不執行腳本或載入遠端資源。

**優先與停用規則：**

- 頁面已有非 `none` 的自訂 Layout 動效時，以頁面設定為準。
- 頁面為「無」或舊佈局未配置時，可以繼承 Skin 預設；因此頁面的「無」不一定代表完全不播放動效。
- 要停用 Skin 預設，可使用 `duration="0"` 的動效檔；這不覆蓋其他頁面的自訂動效。
- 系統「減少動態效果」優先，不因 Skin 配置而繞過。
- 詳情封面的滑動放大、影院推近、光圈揭幕屬獨立 App 偏好，不是此 XML 的模式選項。

純換 Skin 不把預設動效寫進 Layout。原包與衍生包匯出保留已宣告的動效；衍生包選擇不帶 Layout 時，Skin 的 XML 動效仍保留。可用範例見 [PageMotions](../Examples/PageMotions/)。

## 9. 作者 Layout 與個人排列

作者 Layout 放在 manifest 的 `layout` 欄位，不是額外的 `layouts/` 入口。它可描述頁面、組件、分欄、分頁、網格、尺寸、寬度斷點、首頁、隱藏頁面及折疊組件。

使用者可在匯入預覽勾選作者 Layout，或之後選「預覽並套用作者佈局」。勾選時預覽立即切換，確認才提交。包內沒有 Layout 時，不會產生或猜測作者排列。

套用後可透過「編輯佈局」繼續修改，包括新增分欄、增減欄數、拖動分隔比例與頁面編排；這些是 Layout 功能，不會改寫作者原包。詳細操作見[使用指南](USER_GUIDE.md)。

Layout 只能編排已登記的組件，不能重排詳情組件內部的業務語義、增加來源能力或插入任意原生控制項。分享內容不含私人查詢、帳號、收藏、下載任務、簽名 URL 或本機資料路徑。

## 10. 製作與重載作者目錄

建議從 [minimal](../Examples/Skins/minimal/) 開始；需要完整槽、狀態與素材示例時，參考 [full](../Examples/Skins/full/)。

1. 複製單一範例目錄，修改 manifest 的 ID、名稱、版本、作者與授權，避免自己的作品與原範例共用 ID。
2. 修改 theme、components、素材或 XML，保持 manifest 宣告與實際檔案一致。
3. 使用「選取作者目錄並預覽…」，選擇**直接含 `manifest.json` 的目錄**，不是整個 `Examples/Skins`。
4. 修正驗證指出的檔案或欄位錯誤；確認預覽後套用。
5. 之後每次修改檔案，都按「重新載入作者目錄並預覽」。沒有自動監看，也不會未經確認直接改動使用中的主題。

每次重載會建立新的隔離驗證快照，不直接以持續變動的作者目錄繪製。取消或驗證失敗不取代目前外觀。安裝後可從管理窗口匯出自己的包；倉庫範例另於[作者格式](../Examples/Skins/README.md)的「產生、打包及匯入」提供打包工具與命令。

### 包內檔案職責

| 檔案／欄位 | 職責 |
| --- | --- |
| `manifest.json` | 身份、版本、授權、入口、素材清單與可選作者 Layout |
| `theme.json` | 共用與明暗樣式；可由 `entryPaths.theme` 指定其他路徑 |
| `components.json` | 槽、狀態與組件覆寫；可省略，但明列入口後必須存在 |
| `entryPaths.pageMotion` 指向的 XML | 可選預設頁面動效 |
| `assets` 明列的檔案 | 圖片與字型素材 |
| `preview.png` | 可選展示圖 |

包根直接包含 manifest，不可再多包一層資料夾。未知欄位、槽、狀態或 token 會被拒絕；不要把腳本、Finder `.DS_Store`、未列入的檔案或整份開發目錄一起壓進包內。完整必填欄位、版本與 Layout JSON 語法以[作者格式](../Examples/Skins/README.md)為準。

## 11. 匯出與分享

| 模式 | 內容與身份 | 適合情境 |
| --- | --- | --- |
| 作者原包 | 保留作者 ID、內容及原有作者 Layout，不加入個人覆寫 | 原樣轉交主題 |
| 衍生包 | 合併個人外觀，生成新 ID，保留原作者、授權與來源追溯資訊 | 分享自己的調整版本 |

衍生包可明選「不包含 Layout」「目前工作區 Layout」；原包附有 Layout 時，另可選「作者 Layout」。不包含 Layout 不會移除 Skin 的預設頁面動效。

分享 Layout 會清理組件參數，只留下合法展示結構；收藏排序、私人篩選與列表呈現狀態不作為作者包業務內容分享。不要直接壓縮 Application Support 或偏好目錄代替匯出。

匯出前會提示確認素材與字型再散布授權。生成新 ID、保留作者名稱或通過驗證，都不代表已取得素材修改／再散布權，也不會自動改變原授權。

## 12. 移除、恢復與常見問題

### 移除與恢復的差異

- **移除 Skin**：需確認；目前正在使用該包時切回內建外觀。不刪除工作區、收藏、偏好或下載任務。
- **恢復內建外觀**：先預覽再確認，切換外觀但不移除第三方包，不清除 Layout 中的自訂動效。
- **恢復內建佈局**：是獨立 Layout 操作。只想恢復色彩時不要用它取代「恢復內建外觀」。

### 問題排查

| 現象 | 原因或處理方式 |
| --- | --- |
| 套用後排列不變 | 預設僅換外觀；需明選作者 Layout，且包本身必須包含 Layout |
| 切回內建外觀後排列仍改過 | Layout 已獨立套用；如需預設排列，使用獨立的佈局恢復功能 |
| 個人覆寫不可用 | 先套用第三方 Skin；內建外觀不使用此操作 |
| 明暗切換被拒絕 | 檢查包是否宣告並提供所選變體，不會自動反色 |
| 修改作者檔案後沒有變化 | 使用重載入口並確認套用，不會自動監看 |
| 同 ID 匯入要求替換確認 | 內容摘要不同，先檢視差異；即使版本字串相同也可能需要確認 |
| 預覽後無法提交 | 預覽期間狀態改變，重新載入並預覽最新內容 |
| 字型未按預期顯示 | 核對字型名稱、素材可解碼性及歸屬；無法找到指定名稱時可回退系統字型 |
| 樣式被覆蓋 | 核對組件／槽／狀態優先順序與此 Skin 的個人覆寫 |
| 圖片缺失或整包被拒絕 | 檢查素材 ID、相對路徑、manifest 明列項目、實際格式及大小 |
| 對比度警示 | 部分第三方樣式未達正文 4.5:1；App 不替作者改色，可自行修正或從固定選單恢復內建 |
| 頁面設定「無」但仍有動效 | 該頁可繼承 Skin 預設，依第 8 節檢查 XML 與減少動態效果設定 |

## 13. 格式安全與能力邊界

| 項目 | 上限 |
| --- | --- |
| `.iinaskin` ZIP | 65 MiB；最多 256 個項目，含目錄項 |
| 展開單檔／全包 | 16 MiB／64 MiB |
