# macOS 與 iOS 基礎功能對齊規劃

規劃日期：2026-10-27。更新：2026-10-29，M0 至 M6 已交付；M6 五項擴充的獨立範圍、驗收與限制見下節。實機、真實網站、固定回應、人工操作與播放器證據分開記錄，不以本地 fixture 取代實機或外站串流。

目標是在 macOS、iPhone 與 iPad 上完成一致的「找番 → 收藏 → 選集尋源 → 播放 → 離開 → 繼續觀看」流程，讓作品身份、收藏分類、來源選擇、觀看進度及錯誤處理遵守相同規則。macOS 保留 AppKit 工作區和外部播放器，iOS 保留 SwiftUI 與內建 libmpv；操作方式可不同，資料含義與結果應一致。

## 對齊範圍

### 第一階段共同基礎

| 能力 | 目前 macOS | 目前 iOS | 第一階段交付目標 |
| --- | --- | --- | --- |
| 發現與搜尋 | 推薦、放送、分類搜尋 | 本週放送、Bangumi 搜尋 | 作品搜尋、分頁、放送與詳情基本資訊一致；刷新失敗保留內容，已讀基本資訊與集數可離線查看 |
| 詳情與選集 | 分組選集、資訊子頁、來源操作 | 基本資訊、數字網格選集 | 依真正集數身份操作；正篇／SP／OP／ED 分開，未播不可選，日期未知可尋源 |
| 本機收藏 | 收藏／分類獨立、保留未分類 | M1 版本化作品庫、五類／未分類、搜尋／篩選／排序、資訊快取 | 加入／移除收藏、五種觀看分類、分類篩選、名稱搜尋、離線讀取；允許未分類 |
| 來源選擇 | 多站解析器、精確映射失效阻擋、完整 JSON 管理與候選診斷 | 精確映射保存／重啟重用、配置更新失效、JSON 匯入與手動確認 | 共用完整配置契約、能力判定、啟停與匯入校驗；保存使用者確認的精確映射 |
| 播放交接 | PlayableSelection 保留來源選擇 | M0 已保留 Bangumi／來源身份、線路及配置修訂 | 從詳情到播放保留作品、集數、來源與線路身份；媒體 URL 只作當次播放輸入 |
| 觀看進度 | 實際播放器回報、精確重解析／續播、本地引用與舊事件保護 | M3 實際進度持久保存、繼續觀看、載入後定位與 Files 重新授權 | 保存實際秒數、重啟續看、刪除單項歷史；在線續看重新解析 |
| 下一集 | 手動選擇播放會話、同源接續及可取消的自然 EOF 連播 | 同源精確下一集、預設關閉且可持久設定的自動連播 | 手動下一集與可關閉的同源自動連播；缺集、錯誤或停止不得自動換站 |
| 字幕與彈幕 | 依來源、播放器與外掛能力 | 按集數隔離附件、壞檔保留原內容、持久顯示／過濾偏好及實際時間同步 | 對可用後端提供字幕選擇、本地彈幕、顯示／過濾及跳轉同步；不支援時明示 |
| 可用性 | 桌面工作區、鍵盤、多視窗 | 手機分頁、平板側欄、橫豎屏 | 統一載入／失敗／取消／重試語義及三語字串，保留平台佈局 |

五種觀看分類為「想看、在看、已看、擱置、丟棄」。收藏與分類是兩個概念，觀看完畢不自動改成「已看」。既有舊收藏沒有分類時保留未分類，不推測使用者意圖。

第一階段以共同支援的來源與播放器能力驗收，不要求兩端站點數量相同。先以隨包 fqdm 和一份 JSON／模板型配置建立相容案例；桌面專屬站點及既有功能保留。

### 第二階段共同擴充

| 項目 | 範圍與進入條件 |
| --- | --- |
| Bangumi 帳號與收藏同步 | 第一階段儲存與遷移穩定後加入；先同步收藏分類、匯入遠端收藏及手動重試，不同步觀看秒數、評分或評論 |
| 詳情補充資訊 | 標籤、關聯作品、人物及評論閱讀按使用頻率補齊；不以完整桌面資訊頁阻塞播放核心 |
| 自動尋源與來源訂閱 | 精確映射與失效處理驗證後，再加入可信候選判定及有預覽的配置更新；搜尋規則訂閱與完整來源配置繼續區分 |
| 自動取得點播彈幕 | 逐來源核對授權、集數身份與格式，成功匹配後才附加；仍保留手動匯入與關閉 |
| 連結收藏 | 獨立於番劇作品收藏，保存來源頁身份，不自動冒充 Bangumi 作品 |

下載、BT、直播全站能力、Bilibili／YouTube 專頁、截圖識番、Skin／Layout，以及 iOS 背景播放、畫中畫與 AirPlay，列為獨立擴充。跨裝置資料同步也需另外設計；此規劃的本機功能對齊不會自動使兩台裝置共享收藏或觀看進度。

## 實作順序與交付門檻

每個里程碑應交付可獨立驗收的行為、必要的資料遷移、回歸案例及使用文件。先完成身份與資料契約，再接入有副作用的續播與自動連播。

| 里程碑 | 優先級及規模 | 依賴 | 主要交付 | 完成條件 |
| --- | --- | --- | --- | --- |
| M0 身份與能力契約（已完成） | P0／中 | 無 | 共用身份定義、能力判定、播放事件及錯誤分類；iOS 保留完整播放上下文 | 同一組 fixture 在兩平台得到相同身份；不同來源、季度、集數不得相互碰撞；配置宣告不會啟用平台未實作的能力 |
| M1 本機作品庫（已完成） | P0／大 | M0 | iOS 版本化收藏資料、五類狀態及篩選、舊檔遷移、基本資訊與集數快取；macOS 適配共用分類規則 | 舊收藏數量、身份與原順序保留；可重啟及離線讀取已快取資料；寫入失敗不提前更新 UI；壞檔不被空資料覆蓋 |
| M2 精確來源映射（已完成） | P0／大 | M0；持久化整合需 M1 儲存契約就緒 | 保存使用者確認且成功解析的作品及集數映射；來源配置更新失效處理；可區分的尋源錯誤 | 再次選同一集可復用有效映射；更新配置、停用來源或集數不匹配時停止並引導重新確認；不回退第一集、不暗中換站 |
| M3 歷史與續播（已完成） | P0／大 | M0、M2 | iOS 實際進度保存、繼續觀看入口、重新解析及載入後定位；本地檔案重新授權流程 | 測試影片播放到已知位置後重啟，從該集續播；舊回應不覆蓋新進度；媒體載入失敗不建立成功觀看記錄 |
| M4 下一集與播放操作（已完成） | P0／大 | M2、M3 | 同源下一集、自然結束事件、字幕／彈幕狀態策略及能力提示 | 自然 EOF 僅接續一次；停止、關閉、失敗、切集和直播均不誤觸發；跳轉後字幕及彈幕跟隨實際時間 |
| M5 三端整體驗收（已完成） | P0／中 | M1 至 M4 | macOS、iPhone、iPad 的完整用例及實機核對，對齊文件與發佈說明 | 核心用例、升級資料及真實來源播放分別有證據；所有身份錯配、資料遺失與誤播放問題關閉後，才標示基礎對齊完成 |
| M6 帳號與共同擴充（已完成） | P1／分項估算 | M5 | 分開交付帳號分類同步、補充資訊、尋源／訂閱、彈幕及連結收藏 | 每項有獨立範圍及驗收，不將完成登入視為完成同步，不將新增站點視為整體相容 |

規模表示相對複雜度，並非工期承諾。M1 已提供穩定 ID、儲存與遷移契約，M2 已完成精確映射，M3 已接入持久歷史與續播，M4 已接入同源下一集與播放操作；M5 已完成本節定義的三端基礎對齊驗收。M6 按五項擴充獨立交付，不將登入、單一來源或 fixture 成功擴大為全站、全部帳號或正式發佈驗證。

### M0 交付與驗收（2026-10-28）

- 共用 `PlaybackWorkIdentity`、`PlaybackEpisodeIdentity`、`PlaybackContext`，保留 Bangumi ID、集數類型與原始 sort；來源身份以來源／作品或季度／集數分層及 UTF-8 長度編碼避免碰撞。沿用 `SourceItemRef`／`PlayableSelection`，不遷移既有桌面作品、歷史或來源更新基線的主鍵。
- iOS `SourcePicker → MobileSourceFlow → PlaybackSession → MPVEngine` 保留要求的 Bangumi 集數與使用者實際確認的來源選擇，包含線路、可選品質及配置 fingerprint。交接只消費一次，停用、配置更動或取消後的舊回應不啟播；未關聯來源不編造 Bangumi ID，直接媒體／Files 入口不冒充來源映射。
- 配置修訂採解碼內容的 SHA-256，覆蓋 hosts、route、query identity、目錄、解析及搜尋規則；不把格式 `version: 1` 當內容修訂，也不新增 v1 未知欄位。有效能力取宣告、解析器及平台後端交集，iOS 不因 JSON 宣告而啟用 IINA、下載等操作。
- 共用事件區分解析、載入、成功載入、播放器實際時間、暫停、自然 EOF、停止、取消與分類錯誤；兩個播放器 adapter 保留 session／load 身份。拒絕舊載入、亂序與重複 EOF；seek 預測值不是實際進度。EOF 後重播使用新 load 身份及後端確認，不偽造第二次載入成功。
- `Tests/run-multiplatform-contracts.sh --macos` 與 `--simulator <已啟動 UDID>` 在真正 macOS／iOS Simulator 執行同份身份、配置與事件 fixtures，涵蓋 fqdm、JSON／模板型 Internet Archive、跨來源／季度／集數、配置更新與能力邊界。`Tests/run-ios-sources.sh`、桌面來源／播放回歸及真實 mpv queue smoke 通過。
- 正式 App：iPhone／iPad 模擬器的詳情→選源→錯集拒絕→重試→真實 libmpv 播放通過；iPhone 另驗證播放控制與自然 EOF 後重播。macOS 正式 App 已啟動並操作視窗／本地播放。這些固定回應與本地影片不代表真實網站串流已驗收。
- 已確認可用的配對 iPhone 17 與 iPad Pro；M0 當輪未進行實機安裝、簽署授權或最低系統驗證。實際建置、截圖、回歸與限制見[工作記錄](../history/WORK_LOG.md)。M0 當時尚未交付的 M1 收藏遷移、M2 映射持久化與 M3 觀看秒數保存已於下節交付。

### M1 交付與驗收（2026-10-28）

- 兩端共用 `CollectionStatus.swift`：五種狀態及未分類的含義一致，收藏與分類分開操作。macOS 不再把加入／讀取收藏當成「想看」；已保存分類保留，明確清除分類也不會被舊遠端回應還原，且不發送遠端刪除。
- iOS `library.json` 採明確版本與穩定 `bangumi:<subjectID>` 作品 ID。舊 `favorites.json` 先按原始位元組備份，再驗證暫存新檔並原子啟用；保留原檔、身份、文字、原順序與數量，不推測時間或分類，不雙寫權威資料。未知版本／壞檔阻止覆寫，保存失敗保留已提交畫面，可恢復後重試。
- 收藏頁保留名稱搜尋及排序，新增未分類／五類篩選。基本資訊及完整集數獨立快取，保留載入時間與真正集數 ID／類型／sort；離線或更新失敗仍顯示舊資料，快取損壞不清空收藏。封面使用有容量上限的可重建快取，缺圖顯示佔位；資訊快取不是離線影片。
- 資料回歸通過遷移／重試／壞檔／未來版本／寫入失敗／分類獨立／快取損壞與重建；桌面收藏、Core Data 遷移及 Bangumi 舊回應保護通過。共用分類 fixture 在 macOS 與 iOS Simulator 執行一致。
- 正式 App：獨立 iPhone／iPad 模擬器完成分類、收藏、篩選、模擬斷網與重啟後的詳情／集數讀取；另以舊收藏檔啟動 iPhone App，驗證原檔與備份一致、兩筆身份／順序／文字保留且時間／分類為 nil。macOS 正式 App 操作未分類篩選、獨立收藏與分類控制，退出後重新開庫保持分類。兩端 Debug／Release 建置通過；證據與限制見[工作記錄](../history/WORK_LOG.md)。
- 本輪未重驗實機、最低系統、完整 VoiceOver／視窗尺寸矩陣或真實來源播放；離線 UI 使用固定資訊回應與網路失敗注入，不冒充外站或影片離線驗收。M1 當時未交付的 M2 至 M4 已於下節交付；M5、M6 尚未完成。

### M2 交付與驗收（2026-10-28）

- 共用 `ConfirmedSourceMapping` 保留作品／集數完整身份、精確來源選擇、配置內容 fingerprint 與確認時間。配置型頁面依宣告的 query identity 正規化，保留 `file` 等必要身份，移除追蹤／憑證參數；不保存 CDN／簽名串流 URL、帳號、Cookie 或 header。
- iOS `library.json` 升至 v2，v1 先逐位元組備份至 `library.json.v1.backup`，再驗證暫存檔並原子啟用，收藏／分類／原順序不變。映射及缺集／配置失效狀態獨立保存，移除收藏或重建快取不刪映射；保存／移除失敗不提前更新畫面或啟播。macOS 擴充既有映射 payload，原子更新該集首選來源，保留其他集數與來源連結；舊配置型映射須重確認，不更換 Core Data 主鍵。
- 兩端重用時在線刷新原目錄，重新核對作品、集數、原線路及品質；解析與播放交接邊界再次檢查配置及啟用狀態。停用、配置變更、缺集、錯集、付費／試看及過期回應不形成有效映射，不回退第一集、不暗中換站。網路暫時失敗與其他尋源錯誤分開；iOS 保存來源卡片可重啟恢復，明確移除映射後才解鎖重新選源。
- 補齊 macOS 完整來源 JSON 管理入口，與搜尋訂閱分開；兩端先預覽名稱／ID／網域及能力差異，同 ID 明確替換，原子寫入後停用，清單按 ID 排序。格式錯誤、過時預覽及寫入失敗保留已提交資料；內容修訂不是 schema `version: 1`。
- 資料／來源回歸涵蓋升級、壞檔、寫入失敗、重啟重用、來源排序、配置更新、錯集、缺集、停用、取消及交接前變更；共用契約在 macOS 與 iOS Simulator 均通過。兩端 Debug／Release 建置通過。iPhone／iPad 正式 App 完成錯集拒絕、明確重選、真實 libmpv 播放、重啟後原來源重解析播放與停用阻擋；macOS 正式 App 驗證配置預覽／替換／停用、配置更新阻擋及重啟後原集解析／播放器交接。
- iOS UI 使用固定站點回應及本地測試影片；桌面最終外部播放器 IPC 未連上，未據此宣稱串流成功載入或觀看進度成立。未做實機、最低系統、Intel、完整 VoiceOver／尺寸矩陣或全站播放驗收；證據與限制見[工作記錄](../history/WORK_LOG.md)。M2 當時未交付的 M3、M4 已於下節交付；M5 整體驗收尚未完成。

### M3 交付與驗收（2026-10-28）

- iOS 新增獨立版本化 `playback-history.json`、首頁／播放頁繼續觀看、刪除單項歷史及儲存失敗重試。歷史只保存精確來源上下文或本地引用、實際秒數與完成狀態；不保存 CDN／簽名媒體 URL，不把手動直連冒充可重解析來源。收藏／分類／映射與歷史獨立。
- 成功載入並取得播放器實際樣本後才建立進度；定期及暫停／離開／切集保存，寫入成功才發布列表。壞檔／未來版本阻止覆寫，失敗載入不清零舊進度。session／load／entry lease 防止舊播放器、舊解析及刪除後收尾恢復或覆蓋新歷史。
- 續播重新核對原作品、集數、線路、品質及配置，重新載入目錄與解析；停用、變更、缺集、錯集或過期結果不換站／退回首集。成功載入後才 seek；libmpv 等待 seek 命令、SEEK／PLAYBACK_RESTART 及實際目標時間後才解鎖記錄，預測值與 seek 前樣本不能覆蓋歷史。
- 本地 iOS 檔案採 bookmark、檔案長度與串流 SHA-256；授權失效時重新選檔，同內容改名可續播，不同內容即使同名也拒絕，取消／失敗保留歷史。桌面保存 bookmark 與檔案資源身份，移動原檔可追蹤，同名替代檔不能繼承進度。兩端持有必要的 security scope 到播放結束。
- macOS 保留歷史 v1 與既有主鍵，增加可選精確上下文、本地引用及寫入 owner 保護；配置型來源保留宣告的 `file` query identity，舊配置型歷史不猜測新修訂，要求重確認。iOS 已完成的單集保留重播入口，不推論整季已完結或自動改收藏分類。

### 播放上下文

M0 至 M3 必須持續傳遞下列資訊，而不是只傳 URL：

- 作品：Bangumi ID（有則使用）及本機穩定 ID；片名只是呈現資料。
- 集數：有 Bangumi 關聯時保留其集數 ID、類型及原始排序值；本地影片或未關聯來源使用穩定本機／來源集數身份，不編造 Bangumi ID。按鈕上的數字不能作唯一鍵。
- 來源：來源 ID、作品頁、來源集數身份、線路與品質選擇；Bangumi 集數與來源集數以明確映射連接。
- 配置：可判定配置是否更改的內容 fingerprint，至少覆蓋 hosts、route、query identity、搜尋、播放器及可選彈幕宣告；配置更改後先重新驗證映射。`version` 是格式版號，不能當作內容修訂；M6 新彈幕欄位使用 v2，既有 v1 保持原欄位契約。
- 播放階段：本次 session／load 識別、載入成功、實際時間、暫停、自然 EOF、手動停止、錯誤與取消。
- 進度：有效秒數、可選時長、更新時間及完成／待更新狀態；已完成與等待下一集不可混為一談。

來源映射需先由使用者確認作品與集數，或符合之後明確定義的可信規則，再於解析成功並重新核對確切身份後保存。付費／試看、錯集與過期請求不能成為有效映射；列出候選與顯示同名作品不代表完成匹配。解析出的 CDN／簽名串流 URL、帳號 token、Cookie 及 header 不進入作品庫、歷史或共享測試輸出。

來源能力需取「配置宣告、解析器實作、平台後端」的交集。例如完整 JSON 可以帶有 `download` 或 `iina`，但 iOS 不因此顯示未實作的下載或外部 IINA 操作。

### 儲存與升級

- iOS 舊 `favorites.json` 為 `[Anime]` 裸陣列；M1 以獨立 `library.json` 取代權威入口，M2 v2 加入映射，M6 v3 加入帳號綁定的待同步修訂。舊收藏先備份為 `favorites.json.backup`，v1／v2 作品庫先分別備份為 `library.json.v1.backup`／`library.json.v2.backup`，再寫入及驗證暫存新檔，成功後才原子啟用；遷移可重試，來源資料／備份保留，不同時雙寫兩份權威資料。
- 舊收藏保留 Bangumi ID、快取文字、原排序與收藏狀態。不存在的建立時間不偽造為歷史事實，舊分類設為未分類；遷移不觸發遠端同步。
- 未知的新版本、損壞資料或寫入失敗應顯示可恢復錯誤，禁止回退空庫後覆蓋。macOS 沿用既有 `LibraryPersistence` 與遷移機制。
- 歷史只保存經驗證的來源頁身份。現有桌面歷史 query 白名單與配置的 `queryIdentityParameter` 未完全一致，例如檔案型來源的 `file`；需用配置允許的身份參數測試收斂，不能為保存任意 URL 而放寬憑證邊界。
- 本地影片需平台可持久化的檔案存取引用及失效後重新選檔流程；只保存沙盒外路徑不足以完成 iOS 跨啟動續播。重新選檔不能僅以相同檔名認定是原影片。
- 手動貼入的媒體直連沒有可重解析的來源身份；第一階段保留當次播放，不保證重啟續播，也不將可能帶簽名的 URL 直接寫入歷史。
- macOS 與 iOS 各自保存資料；同型別及同規則不意味著共用資料庫。資料匯出／匯入與跨裝置合併需另列版本及衝突策略。

## 各流程的具體行為

### 收藏與離線

保留現有搜尋和排序，新增觀看分類與篩選。離線至少可讀取已收藏作品的文字、分類、曾成功載入的基本資訊與集數清單、已保存的映射及觀看進度。快取保存載入時間，離線或更新失敗時標示為舊資料；快取可獨立重建，損壞不得清空收藏。封面快取採容量上限，缺圖顯示佔位；不承諾從未載入的內容離線可用。來源可播放性仍需在線重新確認，資料快取不代表影片已下載。移除收藏不連帶刪除觀看歷史、來源配置或影片；刪除歷史也不刪收藏。

M6 的 Bangumi 同步採先存本機、再提交遠端。以本機修改修訂及帳號身份防止舊回應覆寫新分類，未登入或同步失敗保留待同步狀態；匯入遠端清單按 Bangumi ID 去重，不刪遠端清單以外的本機收藏。更換帳號不可把上一帳號的待同步操作送往新帳號。

### 尋源與錯誤

將「沒有候選、缺集、來源停用、配置失效、網路暫時失敗、回應不支援、需要登入／驗證、媒體播放失敗」分開呈現，提供適合的重試、改名搜尋、重新選源或返回操作。不可恢復的錯誤不反覆自動重試。切換來源、作品或關閉頁面後，舊結果不回填，也不觸發播放。

配置匯入的預覽、同 ID 替換、排序與啟用行為在兩端形成共同規則；支援能力不同時顯示具體差異。先驗證既有完整配置路徑，再補缺少的管理入口，不將桌面搜尋訂閱誤當完整來源配置。

### 續播與自然結束

播放器確認載入並回報真實時間後才建立進度；定期保存，暫停、離開與切集時提交最後有效值。續播先依原來源重新解析，載入同一集成功後再 seek，失敗保留歷史並提供重試。清除歷史後，舊 session 的非同步收尾不得把它重新寫回。

只有當次載入的自然 EOF 可觸發下一集，且限制同來源、同目錄分組及原線路；原品質不可用時提示，不能默默切換其他站點。手動停止、播放器關閉、媒體錯誤、取消和直播均不能觸發自動接續。iOS 進入背景維持暫停策略，不在背景自動啟播下一集。

目錄最後一項不代表完季。更新狀態未確認時保留追更入口；只有已確認全集更新且末集自然播完，才依既有桌面規則清理該季續看記錄。多播放器或重播產生的新進度不能被舊的完季查詢刪除。

### 字幕與彈幕

第一階段確保「選軌／匯入／關閉字幕、本地彈幕匯入、顯示開關、基本過濾、跳轉同步」在具備能力的後端有可達入口。iOS 的彈幕顯示、關鍵字及類型過濾偏好改為本機持久設定；內容與檔案附件歸屬實際集數，附件重用須遵守檔案授權，不能跨集沿用。切集先清除上一集的彈幕內容與字幕選擇，再載入目前集數的有效附件。全螢幕、旋轉或重繪不重載影片、不重設時間。M6 自動取得僅接受上節明確綁定與授權範圍，不能以手動匯入成功代替站點集數匹配驗證。

### 驗證層級與既有入口

1. **契約與儲存回歸**：共同 fixtures 先覆蓋身份、映射、遷移、錯誤與事件順序。沿用 [iOS 資料測試](../../Tests/run-ios.sh)、[iOS 來源測試](../../Tests/run-ios-sources.sh)、[iOS 彈幕測試](../../Tests/run-ios-danmaku.sh)、[桌面作品庫測試](../../Tests/run-work-library.sh)、[收藏測試](../../Tests/run-w5-favorites.sh)、[來源測試](../../Tests/run-w3-sources.sh) 及 [播放回歸](../../Tests/run-dependency-regression.sh) 的 `--unit` 模式；依影響範圍補充測試。
2. **建置與正式 App 驗收**：兩端 Debug／Release 建置；macOS 啟動本次產物，iPhone／iPad 使用正式 App 入口。分別保留「資料邏輯、介面流程、真實播放器」證據，不以 fixture 成功宣稱外站播放成功。
3. **真實來源與裝置**：選一個共同配置完成搜尋、選集、解析、實際串流播放、重啟續播；至少一台已授權 iPhone 完成安裝與生命週期驗證。iPad 模擬器寬窄佈局另外測試，實機未測時明示。
4. **相容與發佈門檻**：保留既有桌面站點、外掛與資料行為；Release 不含測試入口。最低 iOS 17／macOS 13.5 是宣告支援範圍，沒有對應運行證據時不標示為已實測。本階段不等同 TestFlight／正式簽署或公證完成。

## 風險與處理順序

| 風險 | 處理 |
| --- | --- |
| iOS 在播放器交接處丟失身份 | M0 已修復；M1 至 M3 沿用完整上下文，不退回僅傳 URL |
| 直接共用桌面資料層引入 Core Data／AppKit 依賴 | 只抽值型別及純規則，以 adapter 接回既有儲存與播放器 |
| 站點配置更新使舊映射失效 | 保存配置修訂，重新核對作品／集數，不以名稱猜測修復 |
| 外部播放器事件與內建 libmpv 不同 | 轉為共同事件，保留 session／load 識別及自然結束原因 |
| 本地檔案權限與實機簽署影響驗收 | M0 即確認可用裝置；M3 單獨驗證檔案授權，驗收受阻時列明未完成項 |
| 帳號同步擴大資料損失風險 | 放在本機遷移驗證後，使用修訂保護及待同步狀態，先限於收藏分類 |
